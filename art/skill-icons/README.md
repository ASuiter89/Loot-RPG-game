# Skill-icon art — source masters

Generated source art for the three later classes' skill icons. Like
`art/hero-walk/`, these are **masters, not shipped assets**: the game reads its
icons from the packed base64 sheet in `src/assets/skillIconsAtlas.js`, so nothing
here is fetched at runtime and the build never touches this folder.

They live in the repo because they are **effectively irreproducible**. The art is
generated by an image model, which is not deterministic — re-running the exact
prompt in `docs/spell-icon-prompts.md` returns a *different* picture, not this
one. Losing these would mean re-arting the set, not re-running a script. The
gitignored `tools/skill-icons/.work/` cache is derived and disposable; this is not.

## Layout

One folder per class; **the filename is the icon key**, which is what
`tools/skill-icons/generate.mjs` looks up.

| Folder | Class | Key prefix | Tile colour |
|---|---|---|---|
| `fortune/` | Fortune-Seeker | `sk_fa_*` | violet `#c08ce8` on `#39204a` |
| `windblade/` | Windblade | `sk_za_*` | teal `#5fd6c8` on `#153c3a` |
| `bloodletter/` | Bloodletter | `sk_la_*` | crimson `#d03a4b` on `#45161d` |

So Chance Shot (`f_a00`) is `art/skill-icons/fortune/sk_fa_chanceshot.png`. The
class routing is automatic — `classForIcon()` in `tools/skill-icons/colors.mjs`
reads the letter after `sk_`, so a correctly-named file gets the right frame with
no further wiring.

## Format

Drop the **raw model output, untouched** — white background and all. Do not
pre-remove the background: keying is a derived step, and keeping the original
means the alpha threshold can be re-tuned later without re-generating art.

| | |
|---|---|
| Size | 1024×1024 PNG (512 is the floor) |
| Background | flat, uniform pure white `#FFFFFF` |
| Content | the bare subject only — **no border, frame, badge or backing plate** |

That last point is the one that breaks things. `tools/skill-icons/compose.mjs`
draws the badge — the class-coloured metal-bead frame, the recessed well, the
inner shadow, vignette and gloss, plus the octagon keystone variant. Art that
carries its own frame double-frames, and worse, the alpha-trim step sizes the
icon to *that* frame instead of to the artwork.

## Pipeline

    art/skill-icons/<class>/<key>.png     masters (committed, this folder)
      -> white-to-alpha key
      -> tools/skill-icons/.work/transparent/<key>.png   (gitignored cache)
      -> compose.mjs  -> 128px class badge (+ '<key>@ks' octagon for keystones)
      -> pack.mjs     -> src/assets/skillIconsAtlas.js   (committed, shipped)
      -> drawn in game at <=64px

Keystones need no separate art — the octagon variant is composited from the same
source PNG, matching the octagonal node frame in the SKILLS menu.

`generate.mjs` skips its (paid) API call whenever a transparent PNG already
exists for a key, so keyed masters flow through the rest of the pipeline for free.

## Prompts

`docs/spell-icon-prompts.md` holds the generation brief: the locked style block,
the three class palettes with their contrast rules, and a subject line for all 90
active skills alongside the borrowed icon key each one replaces.

Two rules from that doc are worth repeating, because they are what makes the set
cohere rather than look like 90 unrelated pictures:

- **Lead with the light colour, not the class hue.** Each icon sits in a dark
  class-tinted well, so a violet icon on the violet well disappears. Gold body /
  violet spark, steel body / teal wind, bone body / crimson blood.
- **Keep directional subjects pointing the same way.** Eight of the thirty
  Fortune-Seeker icons are arrows; if they point in random directions the hotbar
  reads as noise.

## After changing anything here

Re-key, re-compose and re-pack, then run the usual gates — `npm test`,
`npm run build`, `npm run smoke`. The atlas is a base64 blob in a JS module, so
check the bundle size when a large batch lands.
